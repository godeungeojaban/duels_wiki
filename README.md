# Duels Wiki 3.31

Duels Wiki 3.31은 Python 표준 라이브러리 기반 로컬 편집기 + GitHub 저장소 + GitHub Pages 정적 열람 사이트 구조다. Node.js/Next.js/npm은 사용하지 않는다.

## 실행

1. `DuelsWikiEditor.py`를 PC에 둔다.
2. `python DuelsWikiEditor.py`로 실행한다.
3. 첫 실행 시 우측 상단 `GitHub 설정`에서 Fine-grained PAT를 입력한다.
   - Repository access: `godeungeojaban/duels_wiki`
   - Contents: Read and write
4. 편집기는 GitHub 저장소의 `editor/` 최신 파일을 내려받아 브라우저에서 연다.

토큰은 저장소에 올라가지 않고 로컬 설정에만 저장된다.


## 3.30 편집 동작

- 스크롤바는 듀얼즈식 흑청/청색 스타일을 사용한다.
- 그림은 선택 후 그림 탭의 `그림 삭제` 버튼으로 삭제한다.
- Backspace/Delete는 그림/캐릭터 카드/설명 상자 자체를 직접 지우지 않는다.
- 캐릭터 카드와 설명 상자를 한 번 클릭하면 해당 요소 바로 아래의 실제 일반 문단으로 커서가 이동한다. 바로 아래가 이미 빈 문단이면 그 문단을 재사용한다.
- 캐릭터 카드와 설명 상자 모두 더블클릭하면 해당 요소의 편집 창을 연다. 더블클릭 과정에서 불필요한 빈 문단은 생성하지 않는다.
- 요소와 같은 높이의 빈 여백을 클릭하는 경우도 동일하게 요소 아래 일반 문단을 활성화한다.

## 3.30 캐릭터 카드 / 색 프리셋

캐릭터 카드 편집 창에서 높이를 기준으로 듀얼즈 비율, 세로 3:4, 1:1, 누운 3:2, 누운 16:9 비율을 적용할 수 있다. `프로필` 프리셋은 400×400 고정 크기를 적용한다. 카드 이미지는 `cover`와 중앙 정렬을 사용해 카드 전체를 빈틈없이 채운다.

글자색, 강조색, 그림 테두리색, 캐릭터 카드 강조색, 설명 상자 강조색 등 색상 입력에는 접이식 `캐릭터 색` 프리셋이 붙으며 Duels 3.1717의 캐릭터 고유색을 바로 선택할 수 있다. 설명 상자는 제목 또는 본문 중 하나가 비어 있으면 비어 있는 영역 자체를 만들지 않는다.

목차에서는 번호만 섹션 하이퍼링크로 동작하고 제목 문자는 일반 텍스트로 표시된다.

## 저장소 구조

`repository/` 내부가 그대로 GitHub 저장소 루트가 된다. `README.md`와 `VERSION.md`도 이 안에 있으므로 함께 commit된다.

```text
repository/
├─ README.md              저장소 설명
├─ VERSION.md             버전 변경 내역
├─ editor/                 GitHub에서 내려받는 편집기 UI
├─ wiki/                   문서 JSON
├─ media/images/           PNG/JPG
├─ site/build.py           정적 위키 생성기
├─ .github/workflows/      GitHub Pages 자동 배포
└─ git_sync.bat            Git add/commit/pull --rebase/push 자동화
```

GitHub에 올릴 때는 `repository/` 폴더 자체가 아니라 **그 안의 내용**을 저장소 루트에 둔다.

## Git 자동화 / 버전 업데이트

저장소 루트의 `git_sync.bat`(Windows) 또는 `git_sync.sh`를 실행하면 기존 GitHub `main` 이력을 먼저 연결한 뒤 **제품 파일만 업데이트**한다.

- 업데이트 대상: `editor/`, `site/`, `.github/workflows/`, `README.md`, `VERSION.md`, 동기화 스크립트와 `.gitignore`
- 사용자 데이터: `wiki/`, `media/`는 기존 원격 저장소 내용을 그대로 유지
- 새 버전 ZIP을 새 폴더에 풀어 실행해도 원격의 `wiki/`와 `media/`를 먼저 복원하므로, 패키지에 없는 기존 문서/이미지가 삭제 대상으로 잡히지 않는다.
- 완전히 새 저장소일 때만 패키지의 기본 `wiki/_root.json`, `wiki/categories.json`, `media/images/.gitkeep`을 초기 데이터로 올린다.

즉 버전 업데이트 시 기존 문서/미디어/커밋 이력은 유지하고 에디터와 열람 사이트 코드만 교체한다. 충돌이 발생하면 강제 push하지 않고 중단한다.

## 정적 열람

`wiki/`, `media/`, `site/` 변경이 main에 push되면 GitHub Actions가 `site/build.py`를 실행하고 GitHub Pages용 정적 HTML을 배포한다.


## 3.33 업데이트 안전성 변경

- 과거의 전체 `git add -A` 업데이트 방식을 제거해, 새 ZIP에 존재하지 않는 기존 `wiki/` 문서와 `media/` 파일이 삭제로 기록되는 문제를 차단했다.
- 기존 원격 저장소가 있으면 `wiki/`와 `media/`는 원격 `main`을 진실 원천으로 복원한다.
- 제품 파일만 stage/commit/push하므로 버전 업데이트가 사용자 문서 데이터를 건드리지 않는다.

## 3.11 table resizing
표 편집 중 셀을 선택하면 선택 열의 오른쪽 경계, 선택 행의 아래 경계, 표 우하단에 크기 조절 핸들이 표시됩니다. 드래그로 열 너비, 행 높이, 표 전체 크기를 조절할 수 있습니다.

## 3.12 병합 셀 기준 행/열 추가
병합된 셀을 기준으로 행/열을 추가할 때 DOM의 `cellIndex`가 아니라 실제 `rowSpan`/`colSpan`을 펼친 논리 표 그리드를 기준으로 계산합니다. 따라서 병합 폭/높이에 맞는 개수의 셀이 생성되고 기존 병합 구조도 유지됩니다.


## 3.13 표 균등 분배 / 재병합

- 열 균등 분배는 표의 현재 전체 폭을 바꾸지 않고 내부 논리 열만 같은 폭으로 나눕니다.
- 행 균등 분배는 표의 현재 전체 높이를 바꾸지 않고 내부 논리 행만 같은 높이로 나눕니다.
- 병합 셀이 드래그 선택 범위에 포함되어도 선택 범위를 논리 그리드 기준으로 확장해 다시 병합할 수 있습니다.


## 3.14 표 병합 행 구조 수정

- 위쪽 셀만 병합했을 때 아래 행의 셀 경계가 사라져 병합된 것처럼 보이던 문제를 수정했다.
- 병합 전 논리 좌표를 기준으로 각 행의 셀 DOM을 다시 배치해, 병합 범위 밖 행/열 구조가 유지되도록 했다.
- 병합 후 셀별 width를 정리하고 colgroup 기준 열 구조를 유지한다.


## 3.15 디자인 / 표 기능 제거
- 표 편집 기능은 제거되었습니다.
- UI는 Duels 3.1717의 흑청/시안 인터페이스를 기준으로 편집기와 정적 사이트 모두 통일되었습니다.


## 3.17 Duels UI 구조 / 모바일 정리
- 편집/열람 양쪽의 UI 구조를 Duels 본편의 패널, 탭, HUD형 문서 프레임 구조로 재설계했습니다.
- `미분류` 카테고리는 편집기와 정적 사이트 모두 항상 목록 마지막에 표시됩니다.
- 760px 이하 화면에서는 좌측 문서 인덱스를 오버레이로 전환하고 스크림을 제공해 모바일에서도 본문/메뉴가 겹치지 않습니다.


## 3.18 디자인 기준

편집기와 정적 열람 사이트는 3.15의 기본 구조와 시각 디자인을 사용한다. 폰트 스택은 Duels 3.1717의 설명/툴팁 UI와 동일하게 맞췄으며, 3.17의 GitHub SHA 충돌 자동 재시도와 미분류 최하단 정렬은 유지한다.

## 3.19 구성요소
편집 리본의 `삽입` 탭에서 듀얼즈식 `캐릭터 카드`와 `설명 상자`를 삽입할 수 있다. 편집 중 구성요소를 더블클릭하면 내용을 다시 수정하거나 삭제할 수 있다. 캐릭터 카드는 열람 사이트에서 hover 또는 keyboard focus 시 설명 툴팁을 표시한다.
