# Duels Wiki 3.60

Duels Wiki 3.60는 Python 표준 라이브러리 기반 로컬 편집기 + GitHub 저장소 + GitHub Pages 정적 열람 사이트 구조다. Node.js/Next.js/npm은 사용하지 않는다.

## 실행

1. `DuelsWikiEditor.py`와 `run_editor.bat`을 PC에 둔다.
2. Windows에서는 `run_editor.bat`을 실행한다. GitHub의 `DuelsWikiEditor.py`가 로컬보다 새 버전이면 런처를 먼저 교체한 뒤 실행한다. 직접 실행하려면 `python DuelsWikiEditor.py`를 사용할 수 있다.
3. 첫 실행 시 우측 상단 `GitHub 설정`에서 Fine-grained PAT를 입력한다.
   - Repository access: `godeungeojaban/duels_wiki`
   - Contents: Read and write
4. 편집기는 GitHub 저장소의 `editor/` 최신 파일을 내려받아 브라우저에서 연다.

토큰은 저장소에 올라가지 않는다. 기본적으로 PC의 로컬 설정(`config.json`)에 저장된다. 실행 파일 옆의 `token.txt`는 다른 PC나 새 설치에 토큰을 한 번 전달하기 위한 일회성 가져오기 파일이다.

에디터 실행 시 `DuelsWikiEditor.py`와 같은 폴더에 `token.txt`가 있으면 `config.json`의 기존 토큰보다 항상 우선한다. `token.txt`의 첫 번째 유효한 토큰을 `config.json`에 덮어써 저장한 뒤 저장에 성공한 경우에만 `token.txt`를 삭제한다. 읽기 또는 로컬 저장에 실패한 경우에는 파일을 남겨 다음 실행에서 다시 시도할 수 있게 한다. GitHub 설정 화면에서 저장한 토큰은 `config.json`에만 저장되며 `token.txt`를 다시 만들지 않는다.



## Duels.html 데이터 참조

본문·제목·각주·표 셀처럼 일반 텍스트를 입력할 수 있는 위치에서는 `{{=duels(...)}}` 명령으로 게임 원본 데이터를 참조할 수 있다. 문서 JSON에는 실제 수치가 복사되지 않고 명령식만 저장된다. 편집기 열람 화면과 정적 Wiki 빌드가 `https://github.com/LyangNem/Duels/blob/main/Duels.html`의 현재 데이터를 읽어 표시한다.

기본 문법은 다음과 같다. 기존의 `` `https://.../image.png` `` 인라인 이미지 문법과 구분하기 위해 함수식은 반드시 `=`로 시작한다. `DUELS` 대신 `캐릭터`도 사용할 수 있다.

```text
{{=duels("루네프","이름")}}
{{=duels("루네프","이미지")}}
{{=duels("루네프","체력")}}
{{=duels("루네프","스태미나")}}
{{=duels("루네프","칭호")}}
{{=duels("루네프","이동속도단계")}}
{{=duels("레이카","난이도")}}
{{=duels("레이카","난이도별")}}
{{=duels("루네프","기술.평타.피해량")}}
```

`이미지`는 글 흐름 안의 인라인 이미지로 렌더링하고, 그 외 값은 일반 텍스트로 렌더링한다. 캐릭터 참조에는 이름, 칭호, 체력, 스태미나, 이동속도 숫자/5단계, 난이도 숫자/별표, 공격력, 방어력, 캐릭터 타입, 교전 사거리, 역할군을 사용할 수 있다. 기술은 내부 배열 번호가 아니라 `기술.<기술명 또는 평타/스킬/반격기>.<전투 수치>` 형식으로 참조하며 설명/배경 같은 장문 텍스트는 참조하지 않는다.

삽입 탭의 `듀얼즈 참조` 버튼을 사용하면 현재 원본에서 인식한 캐릭터와 필드를 선택해 명령어를 자동으로 삽입할 수 있다. `원본 새로고침`은 로컬 캐시를 무시하고 Duels.html을 다시 읽는다. 원본 조회 결과는 성능을 위해 잠시 캐시되지만 Wiki 문서에는 캐릭터 수치가 저장되지 않는다.

원본 해석기는 캐릭터 객체의 이름/ID, 능력치 필드, 스킬 배열/객체를 구조적으로 탐색한다. 따라서 캐릭터나 수치 자체를 Wiki 코드에 하드코딩하지 않는다. 원본에서 필드 이름이나 데이터 구조 자체가 크게 바뀌면 해당 참조는 `[참조 오류]`로 표시되며 원래 명령식은 문서 데이터에 그대로 남는다.

## 현재 편집 동작

- 그림/캐릭터 카드/설명 상자/표는 Backspace/Delete로 직접 삭제되지 않는다. 각 요소의 삭제 버튼을 사용한다.
- 캐릭터 카드, 설명 상자, 표를 한 번 클릭하거나 같은 높이의 빈 여백을 클릭하면 요소 오른쪽 아래의 편집용 텍스트 커서가 활성화된다. 실제 입력을 시작할 때만 요소 아래 새 문단이 생긴다.
- 캐릭터 카드, 설명 상자, 표는 더블클릭하면 전용 편집 창을 연다.
- 글머리와 번호 매기기는 줄 단위로 적용된다.
- 목차에서는 번호만 섹션 하이퍼링크로 동작한다.

## 현재 표

표 삽입 시 행/열 개수, 테두리 색상, 기본 가로 너비를 지정한다. 높이는 직접 지정하지 않는다. 기본 가로 너비 프리셋은 `400px`이다. 처음 생성된 열의 최소 너비는 동일하게 배분된다.

셀은 명시적으로 개행하지 않는 한 한 줄 높이를 유지하며, 긴 한 줄은 줄바꿈 대신 열을 넓혀 표의 실제 가로 폭을 증가시킨다. 내용이 짧아지면 실제 폭도 다시 줄지만 설정된 기본 가로 너비 및 열 최소 너비 아래로는 줄지 않는다. 편집 창에서 현재 실제 가로 폭을 기본 가로 폭으로 동기화할 수 있다.

표 편집 창에서는 셀별 텍스트/배경색, 열 최소 너비, 행/열 추가·제거, 사각형 셀 병합/병합 해제를 지원한다. 행/열 전체선택과 다중 선택 셀의 배경색 일괄 적용도 가능하다. `열 균등`은 병합 전의 실제 열 기준으로 전체 열을 같은 너비로 배분하되 표의 기본 가로 크기는 바꾸지 않는다. `너비 맞춤`은 열 비율을 유지한 채 표를 편집 블록 폭에 맞추는 토글이며, 끄면 저장된 픽셀 기본 너비로 돌아간다.

## 캐릭터 카드 / 색 프리셋

캐릭터 카드 편집 창에서 높이를 기준으로 듀얼즈 비율, 세로 3:4, 1:1, 누운 3:2, 누운 16:9 비율을 적용할 수 있다. `프로필` 프리셋은 400×400 고정 크기를 적용한다. 카드 이미지는 `cover`와 중앙 정렬을 사용한다.

모든 색상 입력에는 접이식 `캐릭터 색` 프리셋이 붙으며, 이미지 URL 입력에는 캐릭터 이미지 프리셋을 사용할 수 있다. 설명 상자는 제목 또는 본문 중 하나가 비어 있으면 비어 있는 영역을 만들지 않는다.

## 저장소 구조

ZIP의 최상위 폴더가 그대로 GitHub 저장소 루트가 된다. `README.md`와 `VERSION.md`도 이 안에 있으므로 함께 commit된다.

```text
duels_wiki_3.55/
├─ DuelsWikiEditor.py     GitHub에 저장되는 로컬 런처 최신본
├─ run_editor.bat         로컬 실행/런처 업데이트용 (.gitignore)
├─ git_sync.bat           Windows Git 동기화
├─ git_sync.sh            POSIX Git 동기화
├─ README.md              저장소 설명
├─ VERSION.md             버전 변경 내역
├─ .gitignore
├─ editor/                GitHub에서 내려받는 편집기 UI
├─ wiki/                  문서 JSON
├─ media/images/          PNG/JPG
├─ site/build.py          정적 위키 생성기
└─ .github/workflows/     GitHub Pages 자동 배포
```

ZIP 최상위 폴더 자체가 GitHub 저장소 작업 폴더다. `run_editor.bat`만 로컬 전용으로 Git 추적에서 제외한다.

## Git 자동화 / 버전 업데이트

저장소 루트의 `git_sync.bat`(Windows) 또는 `git_sync.sh`를 실행하면 기존 GitHub `main` 이력을 먼저 연결한 뒤 **제품 파일만 업데이트**한다.

- 업데이트 대상: `DuelsWikiEditor.py`, `editor/`, `site/`, `.github/workflows/`, `README.md`, `VERSION.md`, 동기화 스크립트와 `.gitignore`
- 사용자 데이터: `wiki/`, `media/`는 기존 원격 저장소 내용을 그대로 유지
- 새 버전 ZIP을 새 폴더에 풀어 실행해도 원격의 `wiki/`와 `media/`를 먼저 복원하므로, 패키지에 없는 기존 문서/이미지가 삭제 대상으로 잡히지 않는다.
- 완전히 새 저장소일 때만 패키지의 기본 `wiki/_root.json`, `wiki/categories.json`, `media/images/.gitkeep`을 초기 데이터로 올린다.

즉 버전 업데이트 시 기존 문서/미디어/커밋 이력은 유지하고 에디터와 열람 사이트 코드만 교체한다. 충돌이 발생하면 강제 push하지 않고 중단한다.

## 정적 열람

`wiki/`, `media/`, `site/` 변경이 main에 push되면 GitHub Actions가 `site/build.py`를 실행하고 GitHub Pages용 정적 HTML을 배포한다.


## 3.34 업데이트 안전성 변경

- 과거의 전체 `git add -A` 업데이트 방식을 제거해, 새 ZIP에 존재하지 않는 기존 `wiki/` 문서와 `media/` 파일이 삭제로 기록되는 문제를 차단했다.
- 기존 원격 저장소가 있으면 `wiki/`와 `media/`는 원격 `main`을 진실 원천으로 복원한다.
- 제품 파일만 stage/commit/push하므로 버전 업데이트가 사용자 문서 데이터를 건드리지 않는다.

## 3.11 table resizing
표 편집 중 셀을 선택하면 선택 열의 오른쪽 경계, 선택 행의 아래 경계, 표 우하단에 크기 조절 핸들이 표시됩니다. 드래그로 열 너비, 행 높이, 표 전체 크기를 조절할 수 있습니다.

## 3.12 병합 셀 기준 행/열 추가
병합된 셀을 기준으로 행/열을 추가할 때 DOM의 `cellIndex`가 아니라 실제 `rowSpan`/`colSpan`을 펼친 논리 표 그리드를 기준으로 계산합니다. 따라서 병합 폭/높이에 맞는 개수의 셀이 생성되고 기존 병합 구조도 유지됩니다.


## 3.13 표 균등 분배 / 재병합

- 열 균등 분배는 표의 현재 전체 폭을 바꾸지 않고 내부 논리 열만 같은 폭으로 나눕니다.
- 행 균등 분배는 표의 현재 전체 높이를 바꾸지 않고 내부 논리 행만 같은 높이로 나눕니다.
- 병합 셀이 드래그 선택 범위에 포함되어도 선택 범위를 논리 그리드 기준으로 확장해 다시 병합할 수 있습니다.


## 3.14 표 병합 행 구조 수정

- 위쪽 셀만 병합했을 때 아래 행의 셀 경계가 사라져 병합된 것처럼 보이던 문제를 수정했다.
- 병합 전 논리 좌표를 기준으로 각 행의 셀 DOM을 다시 배치해, 병합 범위 밖 행/열 구조가 유지되도록 했다.
- 병합 후 셀별 width를 정리하고 colgroup 기준 열 구조를 유지한다.


## 3.15 디자인 / 표 기능 제거
- 표 편집 기능은 제거되었습니다.
- UI는 Duels 3.1717의 흑청/시안 인터페이스를 기준으로 편집기와 정적 사이트 모두 통일되었습니다.


## 3.17 Duels UI 구조 / 모바일 정리
- 편집/열람 양쪽의 UI 구조를 Duels 본편의 패널, 탭, HUD형 문서 프레임 구조로 재설계했습니다.
- `미분류` 카테고리는 편집기와 정적 사이트 모두 항상 목록 마지막에 표시됩니다.
- 760px 이하 화면에서는 좌측 문서 인덱스를 오버레이로 전환하고 스크림을 제공해 모바일에서도 본문/메뉴가 겹치지 않습니다.


## 3.18 디자인 기준

편집기와 정적 열람 사이트는 3.15의 기본 구조와 시각 디자인을 사용한다. 폰트 스택은 Duels 3.1717의 설명/툴팁 UI와 동일하게 맞췄으며, 3.17의 GitHub SHA 충돌 자동 재시도와 미분류 최하단 정렬은 유지한다.

## 3.19 구성요소
편집 리본의 `삽입` 탭에서 듀얼즈식 `캐릭터 카드`와 `설명 상자`를 삽입할 수 있다. 편집 중 구성요소를 더블클릭하면 내용을 다시 수정하거나 삭제할 수 있다. 캐릭터 카드는 열람 사이트에서 hover 또는 keyboard focus 시 설명 툴팁을 표시한다.



## 3.60 변경

- Duels 참조의 내부 `스킬.N.*` 경로 노출을 제거하고 평타/스킬/반격기 등 기술별 전투 수치 메뉴로 재구성했다.
- `칭호`, `이동속도단계`, `난이도별` 참조를 추가했다.
- 기술에서는 실제 원본에 존재하는 피해량, 스태미나 소모량, 버프/디버프 세기와 지속시간 등의 수치만 선택할 수 있다.


## 3.59 변경

- 듀얼즈 참조 창에서 캐릭터 선택과 가져올 값 선택을 완전히 분리했습니다. 능력치나 내부 필드가 캐릭터 메뉴에 섞이지 않습니다.
- 가져올 값은 자동완성 입력칸이 아니라 `기본 / 원본 능력치 / 스킬` 그룹을 가진 선택 메뉴로 표시합니다.
- 기본 메뉴에는 이름, 이미지, 체력, 스태미나, 이동속도, 난이도, 공격력, 방어력, 캐릭터 타입, 교전 사거리, 역할군을 제공합니다. 원본에서 추가로 찾은 수치 필드와 각 스킬 필드는 자동으로 뒤에 추가됩니다.

## 3.58 변경

- Duels 함수 문법은 `{{=duels("캐릭터","필드")}}` 한 가지로 통일했다. 함수명은 대소문자를 구분하지 않아 `duels`, `DUELS`, `Duels` 모두 해석되지만 편집 UI가 생성하는 표기는 항상 소문자 `duels`다.
- 백틱 기반 함수 문법은 더 이상 함수로 해석하지 않는다. 백틱은 기존 인라인 이미지 병기 기능에만 사용한다.
- 표 자체 또는 셀을 한 번 클릭하면 표/셀 선택만 수행하며 본문 커서를 만들지 않는다. 표 옆 공백을 클릭했을 때만 기존처럼 표 오른쪽 아래에 본문 입력 커서를 만든다.
- 표가 선택된 상태에서 셀 드래그로 다중 선택할 수 있다. 편집 상태가 아닐 때 `Backspace`/`Delete`를 누르면 선택된 셀들의 내용만 한 번에 비운다. 셀 스타일과 표 구조는 유지한다.
- 셀을 더블클릭하면 표/셀 선택 상태를 유지한 채 해당 셀을 본문과 같은 `contenteditable` 편집 상태로 전환한다. 이 상태에서는 `Backspace`/`Delete`가 일반 텍스트 편집처럼 동작하고 셀 전체 삭제 명령으로 처리되지 않는다.

## 3.56 변경
- 듀얼즈 참조 문법은 `{{=duels("캐릭터","필드")}}` 하나만 사용합니다. 백틱은 이미지 병기 문법에만 사용되며 함수 문법으로 해석되지 않습니다.
- 문장형 설명/배경 필드는 참조 대상에서 제외하고 캐릭터 타입, 교전 사거리, 역할군을 각각 참조할 수 있습니다.
- 표의 긴 텍스트는 열 너비 내부에서 자동 개행됩니다.
- 표 생성 뒤에는 별도 편집창 없이 셀 더블클릭으로 직접 편집합니다.
- 표 선택 시 리본에 표 전용 탭이 나타나 너비, 테두리, 셀 너비/배경/정렬, 열 균등, 너비 맞춤, 행·열 구조, 병합을 조절합니다.
- 표가 선택된 상태에서 셀을 드래그하면 사각 영역을 다중 선택합니다. 행/열 일괄 선택 UI는 제거했습니다.
